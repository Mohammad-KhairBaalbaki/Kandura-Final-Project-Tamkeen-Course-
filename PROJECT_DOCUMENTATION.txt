1) مقدمة عن المشروع
هذا المشروع عبارة عن منصة إدارة لمتجر “Kandoura Store” مبنية على Laravel 12، تجمع بين لوحة تحكم للمديرين وواجهات API للمستخدمين. الهدف هو إدارة الطلبات والتصاميم وخياراتها والمدفوعات والفواتير والإشعارات بشكل منظم وقابل للتوسع. النظام يدعم إدارة الصلاحيات والأدوار، والإشعارات (قاعدة البيانات + إشعارات الدفع عبر FCM)، مع تقارير ولوحات مختصرة للمسؤولين.
الفئات الرئيسية: Users (مستخدمون)، Admin (مدير)، Super Admin (مدير عام).

2) أهم التقنيات والبكجات المستخدمة
Laravel 12: لتوفير إطار عمل متكامل وسريع مع ORM (Eloquent)، Routing، Middleware، Queue، Notifications.
الحزم الأساسية من composer.json:
barryvdh/laravel-dompdf: توليد ملفات PDF للفواتير.
kreait/laravel-firebase: تكامل Firebase/FCM لإرسال إشعارات Push.
laravel/breeze: جاهزية المصادقة الأساسية.
laravel/sanctum: توثيق API عبر التوكنات.
spatie/laravel-permission: إدارة الأدوار والصلاحيات.
spatie/laravel-translatable: تخزين وترجمة الحقول متعددة اللغات (مثل أسماء المدن والتصاميم).
stripe/stripe-php: تكامل بوابة الدفع Stripe.
خدمات خارجية مذكورة في .env.example:
Stripe (بوابة دفع).
Firebase/FCM (إشعارات دفع).
MySQL، Redis، Mail (سجلات)، AWS S3 (اختياري للتخزين).

3) أبرز الميزات (Features)
- إدارة الطلبات بالكامل (إنشاء، دفع، إلغاء، تحديث حالة).
- نظام فواتير PDF مع تخزين رابط الملف.
- إدارة التصاميم وخيارات التصميم والمقاسات مع حالات التفعيل.
- سلة المشتريات والكوبونات والخصومات.
- نظام المحافظ (Wallet) وشحن الرصيد.
- صلاحيات وأدوار للمديرين مع واجهات إدارة متقدمة.
- إشعارات للمستخدمين (Database) وإشعارات للوحة التحكم (Database + Push عبر FCM).
- لوحة تحكم إحصائية للمديرين وتقارير مختصرة.
- صفحة خاصة للمستخدم المعطل، وإدارة إعدادات الإشعارات.
- صفحة توزيع الطلبات حسب المدن (Pie Chart).

4) المعمارية المختصرة (كيف يمشي الطلب داخل النظام)
المسار Route يستدعي Controller ثم Service ثم Models/DB.
الأحداث Events مثل DashboardNotificationRequested تُطلق ثم يعالجها Listener (SendDashboardNotification) لإرسال إشعار قاعدة البيانات وPush.
Notifications:
إشعارات المستخدمين: تُحفظ في جدول notifications عبر Laravel Notification.
إشعارات لوحة التحكم: تُرسل للـ DB + FCM بناء على تفضيلات الإشعارات (Notification Preferences).

6) أهم الـ Models والعلاقات (مختصر)
User: hasMany addresses, designs, orders, payments, reviews, deviceTokens, notificationPreferences; hasOne cart, wallet; morphOne image.
Address: belongsTo user, city; hasMany orders.
City: hasMany addresses (name مترجم).
Design: belongsTo user; morphMany images; belongsToMany designOptions, measurements; hasMany itemOrders.
DesignOption: belongsToMany designs; hasMany itemOptionSelected; soft deletes.
Measurement: belongsToMany designs; hasMany itemCart.
Cart: belongsTo user, coupon; hasMany itemCart.
ItemCart: belongsTo cart, design, measurement; hasMany itemOptionSelected.
ItemOrder: belongsTo order, design, measurement; hasMany itemOptionOrderSelected.
Order: belongsTo user, address, payment, coupon; hasMany itemOrders; hasOne invoice, review.
Payment: belongsTo user; hasOne order.
Invoice: belongsTo order; يحتوي رقم الفاتورة والرابط.
Review: belongsTo user, order.
Wallet: belongsTo user.
NotificationPreference: belongsTo user, permission.
Image: morphTo لأي موديل.
DeviceToken: تخزين توكنات FCM للمستخدمين.

7) الإشعارات (Notifications)
إشعارات المستخدمين (Database):
UserAccountNotification: تفعيل/تعطيل الحساب.
UserOrderNotification: تحديث حالة الطلب.
UserInvoiceNotification: إصدار/جاهزية PDF للفاتورة.
UserWalletNotification: خصم/إضافة رصيد أو فشل دفع.
إشعارات لوحة التحكم (Database + Push):
DashboardNotificationRequested Event يُطلق من عدة خدمات/Observers.
SendDashboardNotification Listener يرسل إشعار قاعدة بيانات عبر AdminDashboardNotification ويجهز Push عبر FCM.
Payload موحد غالباً: title, body, data (type/event/ids/url).

8) PDF / Invoice subsystem
توليد PDF عبر App\Services\Global\InvoiceService@orderPdf باستخدام barryvdh/laravel-dompdf.
الـ View المستخدم: resources/views/orders/invoice.blade.php.
التخزين: عبر Api\FileService@uploadFile على قرص public ضمن مسار مثل invoices/order-{num}-invoice.pdf.
الربط بجدول invoices: الحقول num, order_id, total, pdf_url.
ملاحظة: InvoiceService في API يقوم بإنشاء/تحديث الفاتورة، وتخزين الرابط.

9) ملاحظات تشغيل المشروع (Run/Setup)
خطوات عامة:
1. composer install
2. إنشاء .env من .env.example
3. php artisan key:generate
4. php artisan migrate
5. php artisan db:seed (إذا كان هناك seeders مطلوبة)
6. php artisan storage:link (لاستخدام الملفات المرفوعة)
7. تشغيل Queue Worker إذا كانت الإشعارات تعمل بالـ queue: php artisan queue:work
إعدادات إضافية:
Stripe: إعداد مفاتيح Stripe في config أو env.
FCM: إعداد Firebase وبيانات التوكن في الواجهة.
غير متوفر في الكود الحالي: Controller API للـ Admin في المسارات المذكورة.
